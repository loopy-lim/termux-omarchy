# 개발 방식

[English](DEVELOPMENT.md) · [README](../README.ko.md)

## 구성과 검증

Android 화면·입력, native Termux 서비스, PRoot guest 준비, 앱 연동을 각각 관리합니다. 한 구성요소의 변경으로 다른 구성요소의 사용자 데이터나 권한 정책을 바꾸지 않습니다.

| 경로 | 역할 |
| --- | --- |
| `runtime/` | 세션 소유·시작·종료, native·guest 환경, 제한된 설치 모듈 |
| `profiles/` | 개인 인증·서버 주소를 제외한 작업 흐름 예제 |
| `installer/` | 소스·자산 검증, 네이티브 의존성 준비와 새 설치 적용 |
| `input/` | Termux:X11 입력 수정 소스·패치 단계·호스트 검사 |
| `manifests/` | 소스 해시·출처·배포 범위 |
| `tests/` | 회귀 검사 |
| `legal/` | 외부 라이선스·구성요소 목록 |
| `tools/` | 공개 전 검사, 고정 다운로드와 결정적 페이로드 준비 |
| `guest/` | 검토한 이식 가능한 게스트 연동과 IME 설정 |
| `native/guard/` | 고정된 PRoot guard 빌드와 대응 소스 내보내기 |

Python 3.12 이상, zsh, `java`·`javac`가 있는 JDK 17 이상에서 실행합니다.

```sh
python3 -B tools/check_publication.py
```

소스 목록·구문·문서 링크·공개 범위·회귀 검사를 확인합니다. Android 설치·권한 부여·개발 서버 접속·기기 조작은 하지 않습니다. GitHub에서도 같은 호스트 검사를 실행하며, 고정 버전 Gitleaks로 알려진 비밀 정보 패턴을 별도 확인합니다.

manifest는 검토 기록입니다. 코드 검토나 서명을 대신하지 않습니다. 소스 변경 후 diff를 검토해 기대 해시를 의도적으로 갱신하며, 검증 중에 검사기가 자기 기대값을 자동 갱신하게 만들지 않습니다.

## 변경 순서

1. Android 전달·X11 입력·Wayland 처리·앱 동작 중 실패 구간을 구분해 재현합니다.
2. 실패를 검출할 회귀 검사를 추가하고 범위를 제한해 수정합니다.
3. 관련 검사와 공개 전 전체 검사를 실행합니다.
4. 기기·입력·그래픽·프로세스 정책과 관련되면 정확한 후보 해시로 실기기 확인을 합니다.
5. 영어 문서를 먼저 갱신하고 같은 변경에서 한국어 문서를 맞춥니다. 미확인 범위를 표시합니다.

호스트 검사는 임시 경로·합성 데이터를 사용합니다. 일반 타이핑·계정 토큰·무관한 화면은 기록하지 않습니다. 입력 수락은 관찰 도구를 끈 상태에서 이동→두 손가락 스크롤→손 떼기→다시 이동, 물리 클릭·앱 복귀·관련 단축키를 확인해야 합니다.

## 유지할 원칙

- 복구를 이유로 Termux 홈·브라우저 프로필·편집기 데이터·dotfiles를 삭제하지 않습니다.
- 소유자·symlink·해시·부분 설치·프로세스 식별이 불확실하면 멈춥니다.
- 확인된 세션과 자식만 종료하며 광범위한 `pkill`·`killall`을 사용하지 않습니다.
- 시작 명령 성공과 실제 준비 완료를 구분합니다.
- native·guest 그래픽 환경을 분리합니다.
- 권한·OEM 정책 변경은 명시적으로 적용하고 원복 정보를 남깁니다. APK 설치만으로 shell/root 권한이 생기지 않습니다.

## 현재 빌드·배포 근거

`v0.1.0-alpha.2`는 소스 Git 트리와 실험용 바이너리 릴리스 자산을 분리합니다. 최종 설치 트리는 고정 다운로드 88개와 검증한 로컬 패키지 manifest 2개, 총 90개 파일입니다. 다운로드 중 15개는 프로젝트 릴리스 자산, 73개는 업스트림 런타임 입력입니다. 업스트림 Weston `.deb`는 최종 트리에 포함되지 않는 별도 빌드용 다운로드입니다. [배포 준비](DISTRIBUTION.ko.md)를 참고하세요.

내보낸 전체 Termux:X11 소스 아카이브로 Git 소스를 받지 않고 `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64` 오프라인 빌드를 통과했습니다. PRoot guard도 오프라인 재빌드에서 바이너리 바이트가 일치했습니다. 소스·빌드 결과이며 후보의 Android 설치, 실제 JNI 입력, GUI 동작과 새 기기 수락은 별도입니다. `fullFreshInstallVerified`는 `false`입니다.

과거 DEX 재구성 도구는 감사용으로 유지하며 이전 아티팩트가 필요한 중단 조건도 남깁니다. alpha.2 빌드 경로가 아닙니다. 새 빌드는 [전체 소스 드라이버](../input/full_build/README.md), 내보낸 아카이브와 [guard 빌더](../native/guard/README.md)를 사용합니다. API 28 guard는 NDK 27.1.12297006, APK는 NDK 29.0.14206865를 사용합니다. APK 오프라인 빌드에는 아카이브에 명시한 정확한 SDK·Gradle 배포·Maven 의존성 캐시도 필요합니다.

새 후보마다 다음을 유지합니다.

- 업스트림·submodule 식별자, 로컬 패치, 도구와 의존성을 고정합니다. 이전 APK·네이티브 오브젝트·개인 프로필·이전 receipt를 소스 빌드 입력으로 쓰지 않습니다.
- 패키징된 DEX/JNI, 패키지 ID, manifest, 소스 고지와 인증서 호환성을 검토합니다. 검토한 서명 전후의 미서명 페이로드 식별자를 보존하고 정확히 소스에서 빌드한 companion과 APK를 짝지읍니다.
- 전체 대응 소스와 고지를 바이너리와 함께 제공합니다. 구성요소별 라이선스 범위를 유지하며 최상위 업스트림 링크만으로 끝내지 않습니다.
- 사용자 작업 저장 후 정확한 후보 해시에 설치·물리 결과를 기록합니다. 이전 태블릿 관찰을 새 APK의 근거로 옮기지 않습니다.

## 새 기기 수락 검증은 남아 있음

다운로더는 NDK가 필요하지 않고 설치하지 않습니다. 네이티브 준비는 누락된 서명 APT 의존성만 명시적으로 추가하며 업그레이드·제거를 하지 않습니다. 새 자산 설치기는 기본 사용자의 네이티브 ARM64 Termux, API 28 이상, 접근 가능한 Adreno KGSL, 정확히 설치된 APK와 새 데스크톱 상태를 검사합니다. 비공개 런타임·컨테이너·launcher나 불일치하는 companion은 보존하고 거부합니다. 마이그레이션 경로가 아니며 누락·변경된 입력은 중단 조건으로 유지합니다.

새 환경에서 의존성 준비, GUI, 실제 GPU 픽셀, 소리, 일반 키·한글, 스크롤 후 트랙패드 복구, 앱 실행·복귀, 정상 종료·시작과 Android 재시작을 확인해야 합니다. 일반 KeyBridge/Caps 설정은 미해결 선택 기능이며 기본으로 꺼져 있습니다. 설정 검토 없이 일반 설치 수락에 포함하지 않습니다. 기존 의존성이 있는 rootfs 재사용 시험은 새 설치 지원의 근거가 아닙니다.

## 릴리스 절차

실험용 알파는 고정 태그·체크섬·명확한 범위로 공개합니다. 캐시·APK·패키지·키·원본 실기기 자료는 Git에 넣지 않습니다. 릴리스 자산은 소스 트리와 분리하며 소스·라이선스 검토와 깨끗한 빌드가 필요합니다.

깨끗한 checkout에서 검사·비밀 정보 스캔·전체 파일 검토를 마친 뒤 게시하며, 올린 Git SHA가 검사한 커밋과 같은지 확인합니다. CI·실기기 수락·장시간 검증은 각각 구분합니다. 우선순위는 새 기기 수락, 측정 기반 입력 지연 개선과 개발 중 관찰한 간헐적 네트워크·세션 실패 조사입니다. 주사율 요청은 지속 60/144 FPS 근거가 아니며 장시간·재부팅·앱 GPU·모든 원격 흐름도 별도 확인입니다.
