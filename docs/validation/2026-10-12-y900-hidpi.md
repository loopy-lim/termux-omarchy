# Y900 4K HiDPI 실기기 검증

**2026-10-12 최신 검증:** native/guest libxshmfence 공유 ABI를 맞춘 뒤, 4K HiDPI에서 YouTube1080p60 약3분 + Web Code 실제20회 저장 + 미리보기 동시 시험이 **10,965frame/87drop(0.7934%)**로 통과했다. Notion은 로그인된 idle 상태였고 영상 디코딩은 software다. [최신 검증·이전 잘못된 PASS의 정정·남은 패키징 범위](2026-10-12-native-fence-desktop.md)를 우선한다. 아래 기존 guest Chromium/Electron 수치와 당시 미달 판정은 이전 단계의 이력이다. 무지연·무손실 주장은 하지 않는다.

후속 production stop/start와 browser stale-lock 복구·폰트 확인은 최신 검증 문서에 별도 기록했다. [현재 소스·receipt의 scoped manifest](2026-10-12-native-fence-reproducibility.json)는 재현 증거 목록이며 범용 installer 완료를 뜻하지 않는다.

Y900 패널의 실제 3840×2560 출력을 사용한다. Termux:X11 `displayResolutionMode=scaled`, `displayScale=100`; Hyprland scale 2.5로 논리 작업 영역은 1536×1024를 유지한다. 기존 1920×1280 / 1.25와 같은 창·글자 크기이며, 화면 버퍼의 픽셀 수는 4배다. 요청 refresh는 60Hz이며 120/144Hz 수락이 아니다.

브라우저는 성능을 확인했던 XWayland + ANGLE Vulkan을 유지한다. XWayland `force_zero_scaling=true`와 Chromium `--force-device-scale-factor=2.5`를 함께 적용했다. 저해상도 창을 compositor가 확대하는 방식으로 흐려지는 것을 막는다. [Hyprland 공식 XWayland HiDPI 문서](https://wiki.hypr.land/configuring/extra/xwayland/)의 원칙을 따르며, 실제 CDP에서 devicePixelRatio=2.5, screen=1536×1024를 확인했다. Code는 native Wayland 창이다.

`hidpi-start.json`, `hidpi-state.json`, `hidpi-processes.json`에서 출력3840×2560 / scale2.5 / 60Hz, config error 없음, 동일 세션, Quickshell 생존, 프로세스75개·좀비0개를 확인했다. Android 로그에서 실제 AHB width3840/stride3840/height2560 수신과 모든 Present copy의 GPU offload를 확인했다. `hidpi-desktop.png`는 실제3840×2560 화면 한 장으로 코드·브라우저 배치와 표시 상태를 확인한 자료다. 프레임 측정 말미의 이 캡처도 포함된 표본이며 별도 반복 캡처는 하지 않았다.

`hidpi-youtube.json`, `hidpi-editor.json`, `hidpi-edit-latency.json`, `hidpi-youtube-vfr.json`, `hidpi-editor-vfr.json`이 근거다. VFR 후보 역시 1% 미만 기준을 충족하지 못했고 이전 idle wakeup 회귀 위험을 없앤 증거가 없어 원래 false로 복원했다. 최초 설정 중 Android preference helper가 timeout하여 desktop은 안전하게 멈춘 상태로 남았다. ADB의 동일 Termux UID로 preference를 적용·확인하고 새 4K 세션을 시작했다. 이 실패도 `hidpi-apply.json`에 보존했다.

**HiDPI 구현 성공과 4K 동시 작업 무지연 수락은 다르다.** 저해상도 기본 측정의 YouTube0.690%보다 악화되었다. 이 초기 단계에서는 4K 동시 작업 성능이 기준에 미달했다. Notion은 열린 상태였고 개인 문서를 편집하지 않았다. 실제 손 입력→패널 지연, 장시간 발열, remote network는 측정하지 않았다.

프로필 도구: `termux/omarchy_display.py`. 실행 중 세션에서는 설정을 거부한다. 저장 후 `loopy-omarchy stop`, `loopy-display hidpi` 또는 `loopy-display performance` 실행, `loopy-omarchy start` 순서다. performance는 X11 scale200%, Hyprland/Chromium1.25로 같은1536×1024 작업 영역을 유지한다. 관련 없는 설정은 보존하며 원본은 managed root의 `display-before.json`, 최초 4K 전환 이전 파일은 `hidpi-before-20261012`에 남긴다. 다른 legacy X11 앱의 자체 DPI 지원은 개별 확인이 필요하다.

실제 도구로 performance→hidpi 설정 왕복을 실행했다(`hidpi-profile-performance.json`, `hidpi-profile-hidpi.json`). 이어 `hidpi-lifecycle.json`에서 새 세션3840×2560 시작·doctor ready와 프로필 적용 후 커스텀10개 파일 해시 유지가 PASS했다. 실행 중 변경 거부와 설정 변환 idempotence/다중 선언 거부를 별도로 확인한다.

## 브라우저 Wayland 후속 후보

Skia GL compositor + ANGLE Vulkan을 분리하여 시험했다. 직접 바이너리의 첫 후보는 GPU 합성이 software로 떨어져 기각했다. DRM shim/render-node만 추가하면 GBM의 CREATE_DUMB ioctl 실패로 GPU가3회 재시작하여 기각했다. 별도 KGSL GBM 라이브러리/드라이버/EGL 환경까지 함께 지정하자 native Wayland, ANGLE Vulkan/Adreno830, GaneshGL, GPU compositing enabled, crash0을 확인했다(`hidpi-angle-gbm-gate.json`). Wayland에서는 강제 device scale 옵션을 빼야 하며, 모니터 scale로2.5를 받는다. 강제 옵션을 상속한 첫 후보는6.25로 중복 적용되어 수정했다.

이 GBM 후보는 YouTube1080p60+15회 편집에서10,990frame/1,093drop(**9.945%**)이었다. 또한 local H.264 기준3초 프레임에서 녹색·자홍색과 서로 다른 프레임이 섞이는 출력 오류를 발견했다(`hidpi-gbm-pixels-frame.png`). GPU 문자열과 native60FPS만으로 채택하지 않았다.

다음 제한 후보는 `--disable-gpu-memory-buffer-video-frames`로 영상 buffer 경계만 바꾼다. [Chromium 공식 switch 정의](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/public/common/content_switches.cc)에 존재하는 옵션이다. 수정 후 심한 색상/프레임 혼합은 사라졌으나, 무색상표기 H.264에 대해 CPU reference와 색 수치가 달라 명시적 색상표기 fixture를 추가한다. 원본영상 SHA는 host와device 모두 `ffcc8f90a2cc4053f7aa3c86e53c4c2c6c771c727221ce03360011dec83e5007`으로 확인했다. 이 단계의 출력만으로 색 정확성을 PASS로 바꾸지 않았다.

후속 video-buffer 우회도 YouTube1080p60+15회 편집에서10,990frame/632drop(**5.751%**)로 불합격했다(`hidpi-youtube-upload.json`, `hidpi-editor-upload.json`). 15회 저장과 DOM 반영은 성공했다. CPU 기준 대비 무색상표기 영상의 대표 색상 최대 차이38을 확인했으며 색 정확성을 PASS로 변경하지 않았다(`hidpi-upload-colors.json`). 명시적 색상표기 fixture를 준비했지만 성능 기준을 이미 실패했으므로 추가 반복 측정은 진행하지 않고 이 후보도 기각했다. 최종 기본값은 원래 XWayland+ANGLE Vulkan이다. 실험 프로필의 창을 정확한 class로만 닫고 개인 브라우저 두 창은 유지했다.

이 초기 단계의 상태는 **4K HiDPI, 기존 브라우저, Code 및 Bun 로컬 미리보기**였다. `hidpi-final-state.json`에서 출력·프로젝트 응답·기존 Notion 창 존재·실험 창 종료를 확인한다. 원격 인증은 사용자 요청대로 나중에 한다. 개발 미리보기 브라우저는 원격 디버깅 포트 없이 다시 실행했으며 이 작업의 ADB19223–19226 전달을 제거했다. 정식 수락 결과는 HiDPI 및 재시작/설정 보존이고, 당시 guest 경로의 4K 영상 동시 작업 성능은 미달이었다. 이후 native fence 경로 수락은 상단 최신 기록을 참조한다.
