# Termux Omarchy의 개인 셸·키 설정

앞선 [실제 PTY 검사](../build/diagnostics/termux-omarchy-terminal-profile-pty-device-20261009-02/receipt.json)는 zsh 시작 0.148–0.152초, Git alias·Neovim 기본 편집기·fzf·zoxide·입력 제안·문법 강조와 별도 tmux 서버의 Ctrl+A·Alt+1…0 전체 창 전환을 확인했다. [구성 검사](../build/diagnostics/termux-omarchy-terminal-convenience-readonly-device-20261009-01/receipt.json)의 Linux profile hash와 rc source 연결도 일치한다. 기본 Termux의 기존 `.zshrc`는 별도 보존 대상이다. 후속으로 개인 AstroNvim 설정과 81개 잠금 plugin을 오프라인 설치했으며, 설치·시작 검사와 GUI 수락을 아래에서 구분한다. 물리 키 전달·화면 지연의 완료 증거로 사용하지 않는다.

2026-10-09에 새 격리 Linux 사용자 `/home/omarchy`에 적용했다. 실제 현재 Deskweft/KeyBridge TOML과 Mac 셸·tmux 설정을 기준으로 Linux 경로와 설치된 도구에 맞게 구성했다. 기본 Termux HOME과 기존 KeyBridge 설정은 유지한다.

| 동작 | 현재 설정 | 검증 범위 |
| --- | --- | --- |
| 터미널 셸 | `/usr/bin/zsh` | 실제 guest 실행·Git alias, 도구 추가 후 실제 PTY 시작 113–133ms |
| tmux prefix | Ctrl+A, secondary prefix 없음 | 실제 guest tmux 조회 |
| tmux 창 1…10 | Alt+1…9, Alt+0 | 실제 PTY 입력으로 전체 선택 통과 |
| 터미널 글자 크기 | Alt+- 감소, Alt++ 또는 Alt+= 증가 | 실제 Foot 공개 창의 grid 감소/복원; 물리 키 경로 미검증 |
| 글자 크기 초기화 | Ctrl+0 | 설정 적용; Alt+0은 tmux에 전달 |
| 복사·붙여넣기 | Alt+C/V | Foot 설정·Hypr 바인딩 등록; 실제 앱 간 clipboard 미검증 |
| 작업공간/창 보내기 | 기존 Meta+1…0 / Meta+Shift+1…0 | 기존 Omarchy 설정 유지; 물리 전달 미검증 |
| KeyBridge Caps+D/F | evdev 183/184 → XKB `code:191`/`code:192` → 이전/다음 작업공간 | 후속 코드 바인딩 적용·reload 확인; 최신 실제 입력 상태(현재 사용 안내) |

셸 설정은 Linux용 pnpm/Bun/Cargo 경로, 설치된 경우의 Neovim/FVM alias, completion cache와 기존 Oh My Zsh Git alias를 연결한다. fzf/fd/eza/bat/zoxide 및 syntax/autosuggestion plugin은 로컬에 있을 때만 초기화한다. 현재 이 도구들과 Neovim을 서명된 패키지로 추가했으며 새 셸은 `EDITOR=nvim`, vi/vim alias, fzf widget과 두 plugin을 사용한다. 실제 PTY 시작은 3회 0.113–0.133초였고 ZLE option 경고가 없었다. 터미널 없이 강제로 interactive 검사한 경우의 경고와 구분한다. 시작할 때 네트워크 설치나 plugin 다운로드를 하지 않는다. Mac의 개인 환경변수·인증 정보·SSH·셸 기록은 옮기지 않았다. Powerlevel10k 전체 외형, 개인 Neovim의 plugin build·LSP와 FVM 등 전체 개발 toolchain이 모두 준비된 상태는 아니다.

개인 파일은 `~/.local/share/loopy-omarchy-profile/`에 있다. 기존 `.zshrc`와 `.tmux.conf`가 없을 때만 source entry를 만들며, 이미 있는 사용자 파일을 교체하지 않는다. Omarchy는 XDG `~/.config/tmux/tmux.conf`를 먼저 읽으므로 현재 설치본에는 해당 파일 끝에 개인 override를 추가했다. 새 tmux 서버가 이 설정을 사용한다. 이미 실행 중인 다른 tmux 서버의 설정을 강제로 바꾸는 작업은 하지 않는다.

[installer](../termux/omarchy_personal.py)는 실행 CLI가 아닌 `install(home, source, expected)` API다. 검토한 Foot/Hypr/tmux SHA가 일치할 때만 적용한다. 사용자 편집, symlink, 공유 쓰기 권한, 모호한 Foot INI, 부분 적용 journal을 발견하면 덮어쓰지 않는다. 현재 값과 원래 바이트를 확인하는 보호가 있으나 다른 편집기와의 원자적 CAS를 제공하지 않으므로 적용 중 설정을 동시에 편집하지 않는다.

원본과 변경 이력은 `~/.local/state/loopy-omarchy-profile/`에 보존했다. 최초 `a32dc4d2-e638-4fba-966a-5c8ffdfd27dc`는 원래 Foot/Hypr 설정, 후속 `fc38c7bb-caf7-4027-9204-70c4f641aeb0`는 직전 Foot/Hypr 설정과 원래 XDG tmux, 변경 전 개인 tmux source를 포함한다. `owner.json`의 `previousBackup`이 연결된다. 이 API에는 자동 restore 명령이 없다. 복원할 때는 두 receipt의 before/after SHA와 사용자 편집을 먼저 대조해야 하며 최신 backup만 복사하면 최초 설정 전체로 돌아가는 것이 아니다.

[설치 영수증](../build/diagnostics/termux-omarchy-personal-install-device-20261009-02/receipt.json), [실제 tmux 검사](../build/diagnostics/termux-omarchy-personal-cli-device-20261009-03/receipt.json), [Foot 크기 검사](../build/diagnostics/termux-omarchy-personal-font-device-20261009-03/receipt.json)에 정확한 source/config SHA와 결과가 있다. 물리 Meta/Alt 배열 교환, 한글 IME와 현재 KeyBridge의 실제 전체 키 전달은 남아 있다. Termux:X11의 Android 키보드 서비스 연결 상태는 [권한 문서](termux-omarchy-validation.md#권한과-키보드-서비스)에서 별도로 확인한다.

후속 실사용에서 트랙패드를 움직이면 화면 배율이 커진다는 보고가 추가됐다. 위 Foot 글자 크기 설정 검사와 구분해 실제 입력 문제로 조사 중이며, 물리 입력·지연 수락은 아직 완료하지 않았다. APK 교체 전 관찰한 renderer zoom 100%·guest cursor zoom 1과 사용자 확대 순간의 시간상 연관은 확인하지 못했다. 사용자 저장·재시작 승인 후 준비한 Termux:X11 APK를 실제 설치하고 새 세션 시작을 확인했다. 데이터 삭제·앱 제거 없이 기존 키보드·화면 배율 설정을 보존했으며 Linux 런타임 11개 파일·입력 journal·native 명령의 hash와 inode도 유지했다. 설치 후 60.7초 관찰에서는 Chromium·VS Code 창과 같은 세션이 유지됐고, 별도 geometry 60회 표본의 renderer zoom도 100%로 일정했다.

이후 사용자는 트랙패드 클릭은 되지만 포인터는 움직이지 않는다고 확인했다. event7 ABS 제스처와 겹치는 120초 관찰에서 Linux 포인터는 움직이지 않았고, 10회 상태 표본의 capture/focus는 활성 상태였다. 되돌릴 수 있는 `capture=false` A/B 기록에는 hardware 제스처가 관찰되지 않아 효과 판정이 불충분했다. 이후 사용자는 움직이다 두 손가락으로 스크롤하면 멈춘다고 답했다. 이를 대응한 APK SHA-256 `1dfe7a0392a5af5b87db6639345f3fb09a54127a20804ca29c0ca4b4dfad65b4`를 승인 후 설치하고 새 세션 `8632feb3-1d8b-4ef8-84b7-1d247f457695` 시작을 확인했다. 기존 키보드·화면·개인 설정은 유지했지만 해당 APK의 최초 물리 시험은 “처음부터 이동이 안 됨”으로 실패했다. 후속 40초 좌표 관찰에는 외장 마우스와 별도 합성 MOVE가 겹쳤으며, 사용자는 움직인 포인터가 외장 마우스였고 트랙패드는 처음부터 움직이지 않는다고 정정했다. metadata 05는 실제 Lenovo 트랙패드의 한 손가락 이동·두 손가락 입력이 앱 root·nested handler에 도달하고 관찰 표본의 이동 억제 상태가 false임을 확인했다. Linux 포인터 이동이나 해결을 입증하지 않는다. 관찰 도구의 정상 종료·진단 `PASS`도 물리 입력 성공으로 표시하지 않는다. 이후 Linux·VS Code·Chromium을 유지한 입력 캡처 재연결로 이동은 돌아왔지만, 사용자 실제 시험에서 두 손가락 스크롤 후 다시 멈췄다. 일시 복구이며 해결 완료가 아니다. 인터넷 전체 단절·웹 창 종료도 별도 미해결 항목이며, 제한된 네트워크·앱 관찰 성공을 간헐적 문제 해결로 표시하지 않는다. [후속 관찰과 실제 설치](validation/2026-10-09-termux-final-followup.md)

접촉 전환 관찰 후 같은 세션의 포인터가 복구됐으며, 도구를 모두 종료한 뒤에도 사용자는 이동·두 손가락 스크롤이 “계속 정상 동작함”을 확인했다. 개인 설정·실행 앱을 유지한 이전 세션의 복구다. 이후 새 저장·재시작 승인 후 [재발 방어 APK 설치](../build/diagnostics/termux-omarchy-trackpad-lifecycle-install-device-20261009-01/receipt.json)에서 SHA-256 `dd801ee0ae7132144b14a8af93f9bed834733cd8ea65fb070f3db75d0924dc24` 일치를 확인했다. 새 세션 `a57f9028-0c31-4592-a074-0e0dc764eafa`의 [읽기 전용 시작 재확인](../build/diagnostics/termux-omarchy-trackpad-lifecycle-start-recheck-device-20261009-01/receipt.json)은 개인 settings·provider 수정·SSH 기본 config·키보드·화면 설정 보존을 확인했다. Chromium·VS Code를 다시 열었으며, [관찰 없는 물리 입력 시험](../build/diagnostics/termux-omarchy-trackpad-lifecycle-install-device-20261009-01/physical-report.json)에서 사용자는 “이동·스크롤·클릭·Alt+Tab 모두 정상”이라고 확인했다. 이 수정본의 반복 이동·스크롤 후 이동·물리 클릭·Linux 창 전환 수락이며 장시간 사용·절전·회전·복귀 안정성은 별도다.

별도 VS Code 빈 Buffer 쓰기 오류는 실제 Electron 43.7.7의 provider에서 원본 9사례 중 3개 `EFAULT`를 재현하고 54바이트 호환 guard 적용 후 9개 모두 통과했다. [native 적용 02](../build/diagnostics/termux-omarchy-vscode-empty-write-apply-device-20261009-02/receipt.json)는 Code만 정상 종료·재실행하고 기존 Chromium·Linux 세션과 원본 백업을 유지했다. 최신 Sync Now에서 사용자는 “동기화는 진행되지만 테마가 아직 안 바뀜”이라고 확인했다. [후속 읽기 전용 점검](../build/diagnostics/termux-omarchy-vscode-theme-sync-readonly-device-20261009-01/receipt.json)은 시작·종료 marker 각 4회와 `EFAULT` 0회를 확인했지만 `SettingsSkipped`도 3회였다. 이후 [충돌 이유 확인](../build/diagnostics/termux-omarchy-vscode-sync-conflict-reason-readonly-device-20261009-01/receipt.json)에서 설정 충돌로 세 차례 건너뜀을 확인했다. [공식 Accept Remote UI 적용](../build/diagnostics/termux-omarchy-vscode-sync-conflict-ui-accept-remote-device-20261009-01/receipt.json)으로 클라우드 개인 설정을 받아 14,890바이트가 됐고, [읽기 전용 재확인](../build/diagnostics/termux-omarchy-vscode-theme-sync-readonly-device-20261009-02/receipt.json)에서 `Xcode Classic (Dark)`·`material-icon-theme`·글자 크기 16·custom title bar 선택을 확인했다. 원래 로컬 백업을 보존했고 클라우드 업로드를 요청하지 않았다. 별도 서명 검증기 초기화 오류를 수정한 뒤 [정상 Marketplace 설치](../build/diagnostics/termux-omarchy-vscode-personal-theme-install-device-20261009-04/receipt.json)에서 Xcode Theme 5.2.0·Material Icon Theme 5.39.0 두 확장을 설치했다. 실제 테마 표시·전체 확장 동기화 완료는 별도다.

[확장 재점검](../build/diagnostics/termux-omarchy-vscode-extensions-audit-device-20261009-01/receipt.json)의 로컬 lastSync snapshot 기준 개인 확장 127개 중 당시 설치 14개·누락 113개였다. 처음의 빈 skipped 배열은 저장 위치를 잘못 조회한 결과였고, [application storage 재확인](../build/diagnostics/termux-omarchy-vscode-extensions-sync-state-device-20261009-02/receipt.json)에서 누락 113개 모두 skipped 115개 안에 있음을 확인했다. [복구 01](../build/diagnostics/termux-omarchy-vscode-extensions-recovery-device-20261009-01/receipt.json)은 9개 설치 후 OpenAI 확장 90초 timeout으로 중단됐다. 후속 [복구 02](../build/diagnostics/termux-omarchy-vscode-extensions-recovery-device-20261009-02/receipt.json)는 93개 추가 설치로 총 설치 116개를 확인했다. 복구 대상 108개 중 102개 설치를 확인했으며 공식 CLI에서 찾지 못한 6개와 사용자 비활성·ignore·Windows 전용으로 보류한 5개는 남았다. 개인 settings·기존 비활성 확장 2개·앱과 Linux 세션을 보존했고 추가 Sync Now·초기화·재활성화는 요청하지 않았다. 두 테마는 공식 자동 업데이트 UI로 pin을 해제했으며 [registry 재확인](../build/diagnostics/termux-omarchy-vscode-theme-pinning-readonly-device-20261009-03/receipt.json)에서 버전·manifest·개인 settings 보존을 확인했다. [공식 ASAR의 native 검사](../build/diagnostics/termux-omarchy-vscode-signature-module-regression-device-20261009-01/receipt.json)는 정상 서명 패키지 성공·변조 패키지 거부를 확인했으며 검증 우회는 없다.

[복구 후 native 감사](../build/diagnostics/termux-omarchy-vscode-extensions-post-recovery-audit-device-20261009-01/receipt.json)는 등록된 116개 확장의 manifest를 모두 확인해 `PASS`다. [의존성 분석](../build/diagnostics/termux-omarchy-vscode-extension-dependencies-host-20261009-02/receipt.json)에서 추가 설치 가능한 필수 누락은 없고, Java Test의 필수 `redhat.java`는 기존 사용자 제외를 유지했다. 참조된 내장 확장 5개는 앞선 native 내장 확장 96개 검사에 근거한다. 33개 확장의 활성화 시도 기록은 전체 기능 성공을 뜻하지 않는다. sharedProcess에는 선택한 오류 marker가 없지만 renderer `EFAULT` 1회의 발생원은 미확정이다. 테마 화면·확장 실제 기능·원격 편집 수락은 별도다.

개인 클라우드 설정에는 이전 앱 전용 SSH config 경로가 없으므로 동기화 settings를 다시 덮어쓰지 않았다. [기본 SSH config 생성](../build/diagnostics/termux-omarchy-vscode-default-ssh-config-apply-device-20261009-01/receipt.json)은 기존 파일이 없을 때만 mode 0600으로 관리 별칭 파일의 Include를 추가했다. guest의 `ssh -G`가 `loopy-development`를 사용자 `loopy`·주소 `100.80.133.120`으로 해석함을 확인했으며 개인 키 읽기·비밀번호 기록·네트워크 인증 요청은 없었다. 후속 APK 재시작에서도 해당 파일과 개인 settings hash가 유지됐다.

개인 AstroNvim 적용 전의 기본 Neovim/Yazi는 정상 `omarchy-launch-editor <path>` / `omarchy-launch-or-focus-tui yazi <directory>` 경로에서도 표시됐다. [당시 GUI 검사](../build/diagnostics/termux-omarchy-tools-gui-device-20261009-03/receipt.json)는 공개 시험 파일만 사용해 편집·저장·두 창의 정상 종료를 확인했다. PRoot TUI 런처는 [Foot 직접 실행 source](../termux/omarchy-launch-tui)를 사용한다. [추가 도구의 정확한 버전·서명·설치 증거](termux-omarchy-validation.md#추가-개발-도구와-정상-omarchy-실행-경로)를 확인한다. 후속 [원격 검증](../build/diagnostics/termux-omarchy-remote-validation-20261009-01/receipt.json)은 임시 Linux 서버의 SSH 인증·Wayland 앱 표시·공개 입력/저장·종료를 확인했다. 실제 사용자의 서버·인터넷 성능은 미수락이다.

[후속 실제 앱 검사](../build/diagnostics/termux-omarchy-yazi-repeat-gui-device-20261009-02/receipt.json)는 한글·공백·따옴표 파일의 Neovim 저장, 특수 문자가 있는 폴더의 정확한 Yazi 선택, 기존 창 focus와 8회 재실행을 확인했다. Yazi의 정상 DDS 소켓 재생성을 소유 peer로 인증하도록 런타임도 수정했다. [런처·재실행 복구의 상세 증거](termux-omarchy-validation.md#파일-관리자-재실행과-공백-경로)에 실패와 후속 검사를 보존했다. Android/물리 입력이나 실제 원격 연결 완료를 뜻하지 않는다.

## 개인 AstroNvim 적용

[native 설치 기록 02](../build/diagnostics/termux-omarchy-personal-nvim-install-device-20261009-02/receipt.json)은 개인 설정과 잠금 plugin 소스 81개 설치 `PASS`, 누락 0개를 확인했다. 네트워크 다운로드와 build script 실행은 없었고 기존 rc·런타임을 유지했다. plugin 확인 범위는 디렉터리 존재이며, 각 plugin의 실제 기능이나 LSP·외부 빌드 도구가 모두 동작한다는 뜻은 아니다.

[시작 검사 04](../build/diagnostics/termux-omarchy-personal-nvim-guest-start-device-20261009-04/receipt.json)에서 guest Neovim은 exit 0, Astro·Lazy 활성 상태를 보고했다. 첫 공개 파일의 저장된 view가 없어 `E484`가 기록됐으며, 같은 Linux 세션이 별도 자원 감시 오류로 종료돼 전체 검사는 `FAILED`다. 개인 AstroNvim의 GUI·편집 수락으로 표시하지 않는다.

이후 [종료 원인과 복구](validation/2026-10-09-termux-final-followup.md)를 확인하고 [자원 감시 업데이트](../build/diagnostics/termux-omarchy-resources-update-device-20261009-01/receipt.json)를 적용했다. 사용자는 당시 실제 VS Code 동기화·설치 중 세션이 유지됨을 확인했으며 완료 여부는 별도다. 당시 세션의 [원본 bar·background 표시](../build/diagnostics/termux-omarchy-trackpad-browser-state-device-20261009-01/receipt.json)와 이후 [Termux:X11 APK 교체 후 새 세션 시작](../build/diagnostics/termux-omarchy-trackpad-update-start-device-20261009-02/receipt.json)도 각각 확인했다. 응답의 `shellReady=false`는 현재 코드의 고정값으로 shell 부재를 뜻하지 않는다. 개인 Neovim 설정으로 GUI를 다시 열고 편집·저장하는 확인은 별도로 남아 있다.


현재 [통합 workflow installer](../termux/omarchy_workflow_install.py)는 검증한 profile 5개와 rc entry 2개·Foot/Hypr/tmux 설정 및 앱/원격 런처를 고정 payload로 준비한다. 원본 SHA가 다르거나 사용자 rc가 이미 다른 내용이면 기존 파일을 유지하고 적용을 거부한다. 현재 태블릿에서는 파일을 바꾸지 않고 별도 native `workflow-install.json`에 같은 설치를 등록했다. 기존 개인 owner.json/backup은 유지한다. 새 설치의 원본/백업 소유 기록은 workflow journal에 있으며 personal API의 owner.json이나 자동 restore는 만들지 않는다. [설치·실기기 검증](termux-omarchy-installation.md#현재-개발-도구까지-통합한-묶음)을 확인한다. 현재 통합 명령에 서명된 개발 도구 29개의 설치도 연결했다. 현재 기기의 기존 신뢰 keyring과 같은 버전의 재사용을 확인했고, 이후 [실제 빈 container 설치](../build/diagnostics/termux-omarchy-fresh-setup-device-20261009-03/receipt.json)에서 서명된 29개 신규 transaction과 workflow 15개 적용도 확인했다. 정확한 원본 mode 0644/0755와 설치 후 0600/0700을 구분하고 사용자 권한 변경은 보존한다. [새 PTY](../build/diagnostics/termux-omarchy-fresh-pty-device-20261009-01/receipt.json)의 zsh/Git alias와 도구 경로는 통과했다. native bootstrap·새 GUI 시작·전체 새 기기/물리 입력 수락은 남아 있다.
