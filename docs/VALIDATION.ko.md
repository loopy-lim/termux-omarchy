## 기존 시험 기기

Lenovo Y900의 기존 설치에서 사용자가 트랙패드 이동·두 손가락 스크롤 뒤 이동·물리 클릭·Alt+Tab을 확인했습니다. Caps 방향키와 작업공간 전환, Alt+Caps Home/End, Meta+Caps 좌우 창 이동도 확인했습니다. 관찰 도구를 종료한 상태에서 작업공간 전환이 유지됐습니다.

현재 펌웨어의 별도 정책 변경 뒤 Meta+L이 Android를 잠그지 않는 것도 확인했습니다. 물리 한/영 전환과 Chromium의 두 언어 입력, VS Code 창·원격 연결·동기화 재시도도 관찰했습니다. 이 결과는 새 배포 APK·다른 펌웨어·처음 설치하는 기기에 자동으로 적용되지 않습니다.

기존 GPU 시험은 네이티브 Zink/Turnip과 게스트 Freedreno KGSL 경로에서 실제 픽셀을 표시했고 Chromium ANGLE/Vulkan 콘텐츠를 렌더링했습니다. 지속 60/144 FPS, 입력 지연 수치, VS Code GPU 가속과 하드웨어 영상 코덱을 검증한 것은 아닙니다.

## Alpha.2 빌드와 제공 준비

2026-10-10에 고정한 upstream 소스와 재귀 네이티브 저장소 16개로 새 APK를 빌드했습니다. 과거 APK·컴파일용 스텁·서명 키는 빌드 소스에 사용하지 않았습니다. Gradle 작업 102개와 ABI 4개 빌드가 통과했습니다. 별도 소스 묶음을 풀어 SDK·정확한 외부 의존성 캐시만 제공한 오프라인 새 빌드도 통과했습니다.

DEX·리소스·매니페스트를 포함한 네이티브 라이브러리 외의 APK 내용은 일치했습니다. 네이티브 라이브러리는 빌드 경로에 따라 달라 전체 APK의 바이트 재현성은 주장하지 않습니다. 연결 패키지의 실제 파일 3개는 재빌드에서도 일치했습니다.

별도 서명 단계에서 공개 개발용 인증서, v2/v3 서명, 16 KiB 정렬, 서명 전후 내용 440개의 일치를 확인했습니다. 정확한 APK·연결 패키지 해시는 입력 소스 매니페스트에 기록했습니다. 새 APK의 물리 기기 수용 검사는 아직 하지 않았습니다.

PRoot guard는 별도 소스 묶음만으로 오프라인 재빌드해 바이너리 3개와 소스 묶음의 바이트가 일치했습니다. talloc을 수정해 다시 링크하는 경로도 확인했습니다. 외부 파일 74개의 다운로드·크기·해시와 게스트 패키지 36개의 신뢰 키링 서명을 검사했습니다. Weston·게스트·워크플로·한글 입력 payload는 실제 설치 검증기를 통과했습니다.

호스트 검사는 `python3 -B tools/check_publication.py`로 실행합니다. 소스·문서·라이선스 해시와 입력·런타임·배포 회귀 검사를 실행합니다. 비밀 정보 검사는 별도의 고정 Gitleaks 검사와 공개 파일 목록 검토로 보완합니다. GitHub CI, APK 빌드, 권한 동의, 실제 기기 동작은 각각 별도 증거입니다.

현재 alpha.2 호스트 검사에서 런타임·설치 92개, 입력 소스·빌드 30개,
배포·다운로드·guard 38개 검사가 통과했습니다. 키보드 24+29개,
스크롤 22개와 생명주기 16개 그룹도 통과했습니다. 설치 파일 90개를
실제로 조립한 뒤 읽기 전용 설치 검증기로 확인했으며 Gitleaks 8.30.1에서
비밀 정보가 발견되지 않았습니다. 예외는 검토한 공개 체크섬 3개뿐입니다.

최종 APK 소스 묶음은 18,052,499바이트이며 매니페스트 항목 6,237개에
네이티브 소스 16개 트리, 런타임 소스 JAR 62개, 원본 AAR 리소스 984개,
모듈 정보 38개와 라이선스 자료를 담았습니다. 정확한 파일 해시는 영문
검증 기록과 배포 체크섬에서 확인할 수 있습니다.

## 남은 수용 검사

- 새 APK와 연결 패키지의 실제 물리 키·트랙패드 동작
- 새 Android/Termux 환경의 의존성 설치부터 GUI 시작까지 전체 과정
- 일반 사용자를 위한 선택적 Caps remapper 설정
- 입력 지연 실측과 지속 FPS, 네트워크·브라우저·세션 종료 문제
- 화면 복귀·회전·잠자기·재부팅·장시간 사용
- 실제 소리 재생, VS Code GPU·확장, Notion·Figma 편집

Alpha.2는 실험용 바이너리와 설치 코드를 제공하며 `fullFreshInstallVerified`는 `false`로 유지합니다. 기존 시험 기기의 성공과 안정적인 새 기기 배포 완료를 구분합니다.
