# Android 권한과 정책

[English](PERMISSIONS.md) · [설치](INSTALL.ko.md) · [README](../README.ko.md)

## 키보드와 트랙패드

Android와 제조사 펌웨어가 앱에 전달하기 전에 가로채는 단축키가 있습니다. 포커스를 얻거나 APK를 설치하는 것만으로 모든 물리 키를 가져올 수는 없습니다. 검토한 APK를 설치한 뒤 필요한 경우 Android 접근성 설정에서 Termux:X11 키 입력 서비스를 직접 허용해 주세요. 수동 설치 앱은 제한된 설정 허용을 먼저 요구할 수 있습니다. 허용할 서비스와 접근 범위를 확인하고 동의해야 합니다.

Caps 조합은 별도의 호환 KeyBridge 설정과 명시적 입력 연결이 필요합니다. 공개 APK의 협력 기능은 기본적으로 꺼져 있으며, 개인 설정·서비스 APK·동의 표시 파일을 제공하지 않습니다. 다른 기기의 표시 파일을 복사하면 설정이 검증되는 것이 아닙니다. 일반 키와 Alt+Tab도 실제 기기에서 눌림·해제와 앱 복귀를 확인해야 합니다.

앱은 데스크톱을 떠날 때 캡처를 풀고 돌아왔을 때 복구해야 합니다. 새 배포 APK에서의 물리 입력 검증은 별도로 남아 있습니다.

## 권한의 범위

접근성 서비스는 사용자의 Android 동의가 필요합니다. ADB나 Shizuku의 셸 권한, 제조사 단축키 정책, 기기 관리자·루트 권한은 일반 APK 설치와 별개입니다. 설치기는 이 권한을 자동으로 부여하거나 펌웨어를 바꾸지 않습니다.

시험 펌웨어는 현재 Android 사용자의 `Settings.System` 값 `keyboard_combo_win_l`이 `0`이면 Meta+L로 잠그는 동작을 생략했습니다. 사용자가 Linux 화면 유지와 Meta+Caps 창 이동을 확인했습니다. 이 설정은 Android 사용자 전체에 영향을 주며 다른 펌웨어의 지원·재부팅 유지·Meta+L 자체의 Linux 전달을 보장하지 않습니다. 공개 설치기는 이를 변경하지 않습니다. 적용하려면 실제 펌웨어의 처리 코드를 확인하고 원래 값·사용자 번호를 기록해 복원 경로를 확보해야 합니다.

## 프로세스와 종료

터미널 창 하나에서도 브라우저, 확장, 언어 서버와 편집기가 많은 자식 프로세스를 만들 수 있습니다. Android는 Linux 내부 제한과 별개로 이 프로세스를 종료할 수 있습니다. 시험 기기에서는 명시적으로 허용한 셸 정책 변경 뒤 수백 개의 자식 프로세스와 편집기 동기화를 짧게 확인했습니다. 무제한 실행, 메모리 압박 대응, 재부팅 유지에 대한 검증은 아닙니다.

새 설치에는 이 정책 변경이 자동 적용되지 않습니다. 프로세스 한도, 메모리 부족, 앱 오류, PRoot 종료를 구분해서 진단하고 실제 지원되는 설정만 원래 값을 보존하며 변경해야 합니다. 한도만 늘리면 모든 종료가 해결되는 것은 아닙니다.

## 네트워크·소리·계정

Wi-Fi 선택과 무선 장치 관리는 Android 설정에서 합니다. Linux 메뉴는 Android 설정으로 연결하며 게스트 NetworkManager가 무선 장치를 직접 제어하지 않습니다. 소리는 네이티브 호스트 브리지를 사용합니다. 싱크가 준비됐다는 응답과 실제 스피커 재생은 별도 확인 사항입니다.

브라우저·편집기 로그인, SSH 인증, Tailscale 계정은 자신의 기기에서 설정합니다. 개발자의 계정·키·서버 주소는 포함하지 않습니다. 마이크와 녹음 권한은 재생과 별개로 판단해야 합니다.
