설정의 **Omarchy 설치**에서 Android 파일 선택기를 연다. APK에 고정한 카탈로그와 크기·SHA256·추출 항목 수가 일치하는 이미지만 설치한다. 외부 파일 제공 앱은 카탈로그를 바꿀 수 없다. 설치 서비스가 파일 스트림과 임시 디렉터리를 소유하며 화면을 닫거나 회전해도 작업을 유지한다. 취소 시 스트림을 닫고 이번 설치의 임시 파일을 정리한 뒤 다시 선택할 수 있다. 기존 Linux HOME과 버전은 삭제하지 않는다.

2026-10-07 격리 Android VM에서 실제 앱 UID 10228, `untrusted_app` SELinux 컨텍스트로 다음을 실행했다.

[공식 File API](https://developer.android.com/reference/java/io/File#getUsableSpace()).

설치 프로세스가 종료되면 다음 설치 재시도에서 앱 소유 임시 추출 디렉터리를 정리하도록 추가했다. 실제 프로세스 잠금을 확보한 뒤 앱 전용 디렉터리에 있는 설치기가 생성한 UUID 형식의 디렉터리만 정리한다. 다른 이름의 파일·디렉터리와 루트 심볼릭 링크는 보존하며, 내부 링크의 대상도 따라가지 않는다. 실제 자식 프로세스를 종료한 호스트 시험은 수정 전 세 경우에서 임시 파일이 남았고 수정 후 통과했다. 살아 있는 설치 프로세스의 잠금이 풀리기 전에는 정리하지 않는 동작과 기존 HOME·버전 보존도 확인했다.

[Android의 동기 저장 API](https://developer.android.com/reference/android/content/SharedPreferences.Editor#commit())는 저장 성공 여부를 반환한다.

## 원본 세션의 Android 명령 전달

이번 구현은 원본 설정이 시작하는 작업자를 통해 Android 명령을 실제 Hyprland에 전달한다. 고정된 Lua API에 대응하는 작업공간·창·IME 제어 키만 받으며, 임의 명령·Lua·프로세스 인수를 받지 않는다. 작업자는 같은 PRoot 프로세스 트리에 속하고 원본 UNIX 소켓에 직접 연결한다. 세션별 잠금과 순서, 작업 파일 16KiB·128개 배치, 소켓 요청 1022바이트·응답 1MiB·2초 한도를 적용한다. 이전 세션의 작업은 소비하지 않으며 오류에는 입력 내용이 아닌 오류 종류만 남긴다.

정확한 검증 APK `e3cad6d7…`를 일반 Android 앱 UID 10228에서 실행했다. 합성 Android `KeyEvent`가 실제 `KeyboardRouter`와 제품 `DesktopCommands`를 거쳐 열 개 작업공간 전환과 열 개 조용한 창 이동을 모두 수행했다. 원본 Quickshell 표시·닫힘과 터미널 입력 복귀도 확인했다. 임시 한도 128 조건에서 실행한 뒤 이전 설정이 없던 상태와 유효 한도 32로 복구했고, 이전 HOME·전체 이미지·UID는 보존됐다. 모든 빌드 입력 121개와 정확한 실행은 [작업자 체크포인트](validation/2026-10-06-omarchy/checkpoint-production-omarchy-actions.json)에 묶었다.

현재 배포된 SDK 후보 `643486e2…`에는 이 후속 작업자가 아직 포함되지 않았다. 이번 단계는 검증 APK와 소스의 증거다. 제품의 Omarchy 선택·실행·되돌리기 UI, 전체 편집·텍스트·클립보드·앱 실행·테마 연결, 기본 Android 한도에서의 안정성, 실제 GPU·키보드 지연·태블릿 검증은 계속 필요하다. 작업공간 관찰 시간은 별도의 `hyprctl` 조회를 포함하므로 입력 지연이나 key-to-photon 수치로 사용하지 않는다.

원본 Omarchy의 실제 Qt Wayland 입력창에서 편집·Unicode 경로도 연결했다. 별도 검증 APK `2cf90e75…`에서 Android KeyboardRouter → 제품 DesktopCommands → 같은 PRoot 안의 작업자 → 실제 Hyprland/Qt 경로로 Alt+C/V, 잘라내기, 실행 취소·다시 실행, 한글·emoji 삽입과 문자 교체를 확인했다. Unicode 입력 뒤 복사·선택 삭제·붙여넣기와 창 종료 후 기존 foot의 일반 키 입력까지 통과했다. 기존 guest 입력 모듈 다섯 개의 바이트를 그대로 재사용하며 SDK·검증 빌드에서 원본/복사본/기록된 해시를 대조한다. [편집 실행 기록](validation/2026-10-06-omarchy/checkpoint-original-omarchy-editing.json)에 APK·UID·44개 제품 구성요소·142개 보존 입력과 실제 창 상태를 기록했다.

첫 편집 실행 graphics-29는 검증 QML의 지원되지 않는 이벤트로 실패했다. 실제 Qt 오류 로그를 보존하고 해당 이벤트를 제거했다. graphics-30은 빌드·설치만 했으며, Unicode 후 편집 검사를 강화한 graphics-31을 실제 실행했다. 검사 후 입력 작업자 PID 9857의 종료, 기존 HOME·전체 이미지·UID 보존과 임시 프로세스 제한의 정확한 복원을 확인했다. 이 검증은 소프트웨어 VM의 소유한 Qt 창에 해당하며, 터미널·다른 툴킷의 클립보드, Android↔Linux 클립보드 교환, 실제 입력기·물리 키 지연·GPU의 완료 증거는 아니다. 제품 프로필 활성화·전환 복구는 남아 있고 위 배포 APK에는 후속 작업자·편집 구현을 아직 재빌드하지 않았다.
