# 개발 방식

[English](DEVELOPMENT.md) · [README](../README.ko.md)

## 구성과 검증

Android 화면·입력, native Termux 서비스, PRoot guest 준비, 앱 연동을 각각 관리합니다. 한 구성요소의 변경으로 다른 구성요소의 사용자 데이터나 권한 정책을 바꾸지 않습니다.

| 경로 | 역할 |
| --- | --- |
| `runtime/` | 세션 소유·시작·종료, native·guest 환경, 제한된 설치 모듈 |
| `profiles/` | 개인 인증·서버 주소를 제외한 작업 흐름 예제 |
| `installer/` | 소스 검증과 설치 입력 사전 검사 |
| `input/` | Termux:X11 입력 수정 소스·패치 단계·호스트 검사 |
| `manifests/` | 소스 해시·출처·배포 범위 |
| `tests/` | 회귀 검사 |
| `legal/` | 외부 라이선스·구성요소 목록 |
| `tools/` | 공개 전 검사 |

Python 3.12 이상, zsh, `java`·`javac`가 있는 JDK 17 이상에서 실행합니다.

```sh
python3 tools/check_publication.py
```

소스 목록·구문·문서 링크·공개 범위·회귀 검사를 확인합니다. Android 설치·권한 부여·개발 서버 접속·기기 조작은 하지 않습니다. GitHub에서도 같은 호스트 검사를 실행하며, 고정 버전 Gitleaks로 알려진 비밀 정보 패턴을 별도 확인합니다.

manifest는 검토 기록입니다. 코드 검토나 서명을 대신하지 않습니다. 소스 변경 후 diff를 검토해 기대 해시를 의도적으로 갱신하며, 검증 중에 검사기가 자기 기대값을 자동 갱신하게 만들지 않습니다.

## 변경 순서

1. Android 전달·X11 입력·Wayland 처리·앱 동작 중 실패 구간을 구분해 재현합니다.
2. 실패를 검출할 회귀 검사를 추가하고 범위를 제한해 수정합니다.
3. 관련 검사와 공개 전 전체 검사를 실행합니다.
4. 기기·입력·그래픽·프로세스 정책과 관련되면 정확한 후보 해시로 실기기 확인을 합니다.
5. 영어 문서를 먼저 갱신하고 같은 변경에서 한국어 문서를 맞춥니다. 미확인 범위를 표시합니다.

호스트 검사는 임시 경로·합성 데이터를 사용합니다. 일반 타이핑·계정 토큰·무관한 화면은 기록하지 않습니다. 입력 수락은 관찰 도구를 끈 상태에서 이동→두 손가락 스크롤→손 떼기→다시 이동, 물리 클릭·앱 복귀·관련 단축키를 확인해야 합니다.

## 유지할 원칙

- 복구를 이유로 Termux 홈·브라우저 프로필·편집기 데이터·dotfiles를 삭제하지 않습니다.
- 소유자·symlink·해시·부분 설치·프로세스 식별이 불확실하면 멈춥니다.
- 확인된 세션과 자식만 종료하며 광범위한 `pkill`·`killall`을 사용하지 않습니다.
- 시작 명령 성공과 실제 준비 완료를 구분합니다.
- native·guest 그래픽 환경을 분리합니다.
- 권한·OEM 정책 변경은 명시적으로 적용하고 원복 정보를 남깁니다. APK 설치만으로 shell/root 권한이 생기지 않습니다.

## 수정 APK 배포 전

[입력 소스 문서](../input/README.md)의 DEX 패치는 고정한 과거 APK를 대상으로 합니다. 호스트 검사는 동작·연결 구간을 확인하지만 새 upstream checkout에서 APK를 완전히 재빌드했다는 뜻은 아닙니다.

배포 전에는 upstream 전체 소스·submodule·도구·입력을 고정하고, 수정 내용을 검토 가능한 소스 변경 또는 재현 가능한 패치 과정으로 정리해야 합니다. 개인 파일·이전 receipt·로컬 APK 없이 빌드하고 패키지·manifest·서명 호환성을 확인해야 합니다. 바이너리와 동등하게 접근 가능한 전체 대응 소스·고지를 제공해야 하며 최상위 upstream 링크만으로 끝내지 않습니다.

그 다음 사용자 작업 저장 후 데이터 삭제 없이 설치하고 정확한 후보에서 물리 입력·정상 종료·시작을 확인합니다. 이번 소스 알파에는 수정 APK를 배포하지 않으며, 이전 실기기 APK를 이 저장소에서 재현 가능하다고 표시하지 않습니다.

## 새 기기 설치와 릴리스

native Weston·PRoot guard·guest adapter·workflow·선택 IME/개발 패키지·입력 APK의 고정 획득·빌드를 완성해야 합니다. 누락된 입력 검사를 끄지 않습니다.

기존 native 의존성을 재사용한 rootfs 시험과 새 Android 설치를 구분합니다. 새 환경에서 의존성 준비→GUI→GPU 픽셀→키보드→트랙패드→앱 실행→화면 복귀→정상 종료·시작→Android 재시작을 확인해야 합니다.

소스 알파는 고정 태그·체크섬·명확한 범위로 공개합니다. 캐시·APK·패키지·키·원본 실기기 자료는 Git에 넣지 않습니다. 바이너리는 전체 소스·라이선스 검토와 깨끗한 빌드가 별도로 필요합니다.

깨끗한 checkout에서 검사·비밀 정보 스캔·전체 파일 검토를 마친 뒤 게시하며, 올린 Git SHA가 검사한 커밋과 같은지 확인합니다. CI·실기기 수락·장시간 검증은 각각 구분합니다. 남은 우선순위는 설치·빌드 재현, 측정 기반 지연 개선, 간헐적 네트워크·세션 실패 조사입니다.
