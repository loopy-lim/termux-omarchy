# 실사용 입력 권한과 GPU 화면 합성

사용자 요청: 키보드·마우스 연결 시 GNU/Linux·Omarchy 같은 데스크톱 입력 경험을 제공하고, 실사용 조건으로 가능한 기능을 완성한다. GPU 가속도 명시적으로 포함한다.

## 동작

- 물리 주변기기가 연결되면 실사용 준비 화면을 한 번 안내한다. 설정에서 언제든 다시 연다. 접근성 입력 우선권, 알림, 배터리 관리, 연결 장치와 그래픽 경로의 현재 상태를 보여준다.
- 접근성이나 시스템 설정 승인은 Android의 사용자 승인 화면에서 이루어진다. 실패·거부 상태에서도 데스크톱은 동작한다. 광범위 파일 권한은 요청하지 않으며 공유 파일 제공자를 사용한다.
- 기본 홈 앱은 선택 사항이다. HOME 후보로 등록하고 Android의 홈 역할 승인 창을 연다. 태블릿 전환은 다른 Android 홈 앱으로 복귀한다.
- 전체 화면의 활성 데스크톱에서 물리 마우스 입력을 캡처한다. Android 화면, 설정 대화상자, 포커스 손실, 장치 분리에서는 반납한다. Ctrl+Alt+Esc는 입력을 반납하고 Android 조작 버튼을 복원한다. 다시 데스크톱에 들어가면 캡처를 재개한다.
- 접근성 서비스 중단과 재연결에서 눌린 입력을 해제하고 전달 상태를 갱신한다. 이미 캡처된 포인터의 모션을 중복 전달하지 않는다.
- Android EGL/GLES가 Wayland 공유 메모리 표면의 순서, 위치, 색상 변환과 알파 합성을 처리한다. 초기화·컨텍스트 실패는 CPU 출력으로 복구하며 사용 경로와 실패 이유를 진단에 남긴다. Surface 분리·교체는 Linux 프로세스를 유지한다.
- 고해상도 표면은 highp 텍스처 좌표를 사용한다. fragment highp가 없는 GLES2 장치에서 1024픽셀보다 큰 출력·텍스처는 CPU로 복귀해 작은 글자의 픽셀을 보존한다.

## 범위와 한계

Android 28 이상, target SDK 36과 기존 Java/Rust/C 빌드를 유지한다. 각 코드 파일은 500줄 이하로 유지한다. 루트나 OEM 비공개 API를 사용하지 않는다. GPU 경로는 Android 호스트의 합성과 출력이다. Linux Sway·브라우저·앱은 현재 pixman/wl_shm 경로이므로 게스트 3D 가속이나 DMA-BUF를 주장하지 않는다. 접근성 API도 Android/OEM의 예약 단축키를 모두 탈취한다고 보장하지 않는다.

## 검증

호스트 입력 정책 시험, native 장면/픽셀/수명 시험, Android 앱·시험 APK 빌드, 새 ARM64 VM의 실제 화면·브라우저·편집기·세션 복귀·권한 화면·긴급 입력 반납 시험을 실행한다. GLES vendor/renderer를 기록한다. SwiftShader VM의 통과는 실제 Y900 GPU 성능이나 물리 주변기기 수락이 아니다. 연결된 물리 기기가 없으면 그 한계를 결과에 명시한다.
