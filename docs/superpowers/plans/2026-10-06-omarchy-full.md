# Actual Omarchy Support Implementation Plan

> **For agentic workers:** Execute this plan task by task using the executing-plans workflow. Research delegation is limited to the explicitly invoked research skill; no automatic implementation delegation is required.

**Goal:** Run actual Omarchy on the Y900 with all its capabilities and the user's native keyboard/mouse, Wayland, GPU and everyday-use requirements.

**Architecture:** Separate pinned Arch ARM64 runtime and original Hyprland/Quickshell session. Android handles its hardware through explicit bridges; actual Linux/system integration supplies features requiring kernel or PID 1 ownership. A scoped ARM64 VM supplies reference evidence, not tablet acceptance.

**Tech Stack:** Python build tools, Pacman/Arch ARM64, C++ Aquamarine/Hyprland, Qt/Quickshell, Rust Wayland/Android EGL, Java Android host.

**Spec:** [Full design](../specs/2026-10-06-omarchy-full-design.md)

## Global constraints

Preserve the full 158-package/51-manual/119-QML scope. No Sway substitution, no missing-package skipping, no broad completion claim from manifests or builds. Preserve user HOME, KeyBridge, Android data and existing sessions. Real-device calls must use Y900/TB522FU only. No flash/unlock/wipe/publication. Every source and artifact is pinned and current evidence is scoped by exact bytes. Modules are at most 500 lines.
